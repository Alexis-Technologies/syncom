# Compared with alternatives

syncom is a data engine that keeps records on the device and replicates them between nodes. That
puts it where four kinds of tools meet: the **CRDT libraries** (Yjs, Automerge, Loro, Jazz), which
merge documents and leave storage and queries to you; the **local-first databases** (RxDB, PouchDB,
TinyBase, Dexie Cloud, Fireproof), which store and query records and sync them through a backend;
the **peer-to-peer and event-sourced stores** (GUN, OrbitDB, Evolu, LiveStore); and the **sync
services** (ElectricSQL, PowerSync, Zero, Triplit, InstantDB), which replicate a server database to
clients. The table compares syncom with eighteen of them, with every feature in one table rather
than a few favourable rows. syncom is the first column. It is tinted, and on a wide screen it stays
pinned next to the features while the table scrolls, so every row can be read against it.

How fast each one is, measured on the same scenarios, is on the [Benchmarks](/guide/benchmarks)
page.

## What the table shows

- **A database or a merge, rarely both.** The CRDT libraries merge text and lists
  character by character, but they have no queries, no indexes and no schema (Loro and Jazz
  have partial ones). The databases and services do query, but most of them resolve a conflict
  per document or per revision, or let the server decide. syncom sits between the two. It
  gives you records with a schema, Mango queries, indexes and unique keys, and it merges
  concurrent writes field by field, with counters that add up. That makes it a database that
  merges, not a document CRDT: it has no text or sequence type.
- **Few sync without a server of their own and still check what they receive.** Nine of the
  nineteen need no server from the project to sync: syncom, Yjs, Automerge, Loro, RxDB,
  PouchDB, TinyBase, GUN and OrbitDB. Of those nine, only syncom and RxDB validate writes
  against a schema. Only syncom, RxDB and PouchDB let the node serving the data reject a write
  before it spreads (RxDB through its server plugin, PouchDB through CouchDB's
  `validate_doc_update`). In syncom the host runs the same validators, hooks and scopes on a
  peer's op that it runs on its own writes.
- **Counters that converge are rare.** syncom, Automerge, Loro and Dexie Cloud have them; Dexie
  Cloud replays the operation on its server. Everywhere else, two replicas that increment the
  same number at the same time lose one of the increments.
- **A history that cannot be altered usually cannot be purged either.** Five keep a
  tamper-evident history: syncom, Automerge, Jazz, Fireproof and OrbitDB. Automerge, Fireproof
  and OrbitDB cannot take a payload back out of it. syncom's `purge()` removes the payload
  from the op log and keeps the record of the operation; Jazz erases a CoValue on its server.
  Zero, Triplit, InstantDB and TinyBase can delete for good because they keep no history to
  begin with.
- **Unique keys across replicas.** Only syncom and InstantDB enforce a unique key. syncom
  checks it on every write and reports a clash between two peers as a `conflict` event. In the
  others the key is per device, or it is checked only where the server writes to Postgres.
- **Where syncom is behind.** It has no collaborative text and no list CRDT (Yjs, Automerge,
  Loro and Jazz do). Ops are not signed, and end-to-end encryption is a recipe, field by field
  (Jazz signs and encrypts; Evolu encrypts). There are no UI bindings and no React Native target, and it is
  not yet on npm.
- **Some are no longer moving, or are moving away.** PouchDB has not published since June 2024,
  and GUN's npm release is from July 2025. Triplit's last release was July 2025 and its site is
  gone. Instant Cloud closed to new signups and shuts down on 2027-08-31; InstantDB stays open
  source for self-hosting. Jazz's npm `latest` (0.20) is not the version its site documents
  (2.0, in alpha).

## How the table was made

- **From the code, not the README.** Each library was read at its latest npm version in
  October 2026: the published tarball, plus the official docs. Where the docs and the code
  disagree, the cell follows the code and a footnote says so. A service is judged as client
  and server together; the cell says which side a feature lives on.
- **What ✅ means.** A feature counts as ✅ only when it ships in the project's own packages,
  and the package is named in the cell. A third-party package, a paid tier or an experimental
  flag makes it ⚠️, with the reason given.
- **The syncom column is this repository** at the version on the page, checked against
  its tests.
- **The data is in the repository.**
  [`docs/comparison.json`](https://github.com/Alexis-Technologies/syncom/blob/main/docs/comparison.json)
  keeps every cell with the file or page it was decided from, so you can check any of them.
  `pnpm docs:comparison` renders it into this page. If a cell is wrong, open an issue or edit
  the data; the table is generated from it.

## Where each one fits

- **syncom**: records with a schema, queries and live views, kept on the device and replicated
  between servers, browsers and peers. Any node can host, so no service is needed, and the
  history is verifiable and can be purged. Zero dependencies.
- **Yjs, Automerge, Loro**: collaborative editing. Text, rich text, lists and trees merge
  character by character; storage, queries and access control are yours. Yjs has the largest
  ecosystem of editor bindings, Automerge keeps the full history, and Loro has the richest
  container types.
- **Jazz**: an app framework built on signed, encrypted CoValues, with groups and roles. It needs
  a sync server (Jazz Cloud or self-hosted).
- **RxDB**: a reactive JSON-document database with many storages and replication plugins. Disk
  storage on Node.js and several features are Premium.
- **PouchDB**: CouchDB's replication protocol in the browser, with a CouchDB as the hub.
- **TinyBase**: a small reactive in-memory store with many persisters and a simple sync protocol.
- **Dexie Cloud**: IndexedDB with a hosted (or licensed on-prem) sync service, realms and roles.
- **Fireproof**: an encrypted, content-addressed document ledger that syncs through its cloud.
- **GUN, OrbitDB**: peer-to-peer graphs and logs, over GUN's own mesh or libp2p and IPFS.
- **Evolu**: end-to-end encrypted SQLite on the device, synced through a blind relay.
- **LiveStore**: event sourcing into SQLite on the client, with a central sync backend.
- **ElectricSQL, PowerSync, Zero**: Postgres (or MongoDB, for PowerSync) is the source of truth.
  Clients get shapes, buckets or query results, and writes go through your API.
- **Triplit, InstantDB**: a sync database with its own server, query language and permissions.
