# Invariants

What syncom guarantees, each with the tests that hold it. The ids are stable; a test named here
is a plain-string title in `tests/` (`tests/package/invariants.test.js` fails when one is renamed
without its row, or when an id names no test). The prose behind them is
[Guarantees and limits](docs/guide/sync.md#guarantees-and-limits) and
[Versions and history](docs/guide/versions.md).

The prefixes, in the order the table keeps (`tests/package/invariants.test.js` holds an id to a prefix listed here,
and the rows to this order, numbered within a prefix):

| prefix | area |
| --- | --- |
| `SYNC` | replication: convergence, delivery, resume, bootstrap, signatures, own streams |
| `OPS` | the op model: kinds of a field, own keys, counters |
| `KIND` | kinds as plugins, a plugin missing, plugin methods |

| `LIST` | lists and texts: elements, moves, embeds |
| `SEQ` | the sequence engine and its rope |
| `RLE` | run-length content |

| SEC-3 | The sealing of records is a plugin — an encrypted write without `encryption` is `PLUGIN_MISSING`, at `open()` and per call, and no RSA pair is made — and a backend wrapped by `atRest()` holds no plain text: every file is ciphertext under one key, read back by that key alone (`DECRYPT_FAILED` with its reason otherwise), the backend contract holding through it on both platforms. | `an encrypted write without the plugin is PLUGIN_MISSING, at open() and per call`; `atRest: every file through the wrapper is enc1: ciphertext, nothing plain in the backend, and the key reads it back`; `the wrong key, a plain file and a torn one are DECRYPT_FAILED, each with its reason`; `the options are checked when the wrapper is made`; `encryption (browser)`; `a ciphertext is bound to its file name: one copied over another does not decrypt` |
| BACK-1 | A layered backend reads as a multi-level cache and writes to every layer in list order: a read is the first hit top down (filled upward), a write or removal lands on every layer — through, or from the write-back queue the top answers ahead of, which is drained before any lower layer is consulted, so nothing stale is read from below — `create` is exclusive across the layers, and the backend contract holds through the stack, over memory and over the disk. | `through: a write lands on every layer in order, a read is the first hit filled upward, list is the union`; `create is exclusive across layers: a file on the disk below is a lock, whatever the memory holds`; `back: a write resolves when the top has it, the rest land from the queue; flush awaits it; nothing stale is read from below`; `back: a queued call that failed is reported by flush, once; close flushes and closes the layers that close`; `a storage over a memory layer ahead of the disk: what lands below reopens alone, a fresh top fills on read`; `fsi write { atomic } lands whole: a rename puts it in place, a temporary is never listed, an append after it goes to the new file`; `back: every queued failure is told to onError and counted; a read that waits for the queue never throws one` |
| SCHEMA-1 | The schema is a plugin: without `schema` a schema or a validator given to `open()` is refused (`PLUGIN_MISSING`), records are untyped and `migrate()`/`check()` are refused the same way; with it the lean core has its collections, validates a local write and reads an older record through the lens exactly as `/all` does. | `without the plugin a schema or a validator is PLUGIN_MISSING, records are untyped`; `with the plugin the lean core has its collections, validates and reads through the lens`; `Schema (lean core, plugins by hand)` |
| TEL-1 | Telemetry is a plugin: the core records through a writer — the disabled one when none was given, so every write path brackets its work the same way on or off — takes a writer given to `open({ telemetry })` contained — a method it lacks records nothing, one that throws is swallowed, `withSpan` runs the work exactly once — and refuses an OpenTelemetry api or tracer without `telemetry` (`PLUGIN_MISSING`); with the plugin the api and the pre-built instances are adapted on the lean core as on `/all`. | `without the plugin an api or a tracer is PLUGIN_MISSING; a writer is taken as it is`; `with the plugin the api and the pre-built instances are adapted, on the lean core`; `the disabled writer still runs the callback and answers everything`; `a writer with only enabled and withSpan`; `a writer whose every recording method throws`; `withSpan that throws, never calls, or calls twice runs the work once and returns its result` |
| QUERY-1 | The cursor is a plugin: without `query` a collection's `select()` and `count()` throw `PLUGIN_MISSING` while the catalog keeps indexing every write, so the plugin arriving reads what was indexed all along; with it the lean core answers and watches a query as `/all` does. | `without the plugin select() and count() are PLUGIN_MISSING; the catalog still indexes`; `with the plugin the lean core answers a query from the catalog, and watches it`; `Queries (lean core, plugins by hand)` |
