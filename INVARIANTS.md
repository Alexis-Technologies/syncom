# Invariants

What syncom guarantees, each with the tests that hold it. The ids are stable; a test named here
is a plain-string title in `tests/` (`tests/package/invariants.test.js` fails when one is renamed
without its row, or when an id names no test). The prose behind them is
[Guarantees and limits](docs/guide/sync.md#guarantees-and-limits) and
[Versions and history](docs/guide/versions.md).

| id | guarantee | tests |
| --- | --- | --- |
| SYNC-1 | Two nodes that have applied the same set of ops hold the same records, whatever the order — the documented counter/reset and kind-clash cases apart. | `two nodes converge in both directions`; `concurrent writes converge: registers by last writer, counters by sum`; `a random workload over a mesh converges (seeded)`; `a random walk under hazards — drops, duplicate pages, a reopen — still converges (seeded)` |
| SYNC-2 | An op may arrive more than once; applying it again changes nothing. | `applying the same op twice is a no-op`; `applyRemote: in order per origin, duplicates and gaps skipped` |
| SYNC-3 | A peer's op is checked for its shape and its skew before anything reads it; a malformed one is counted, neither logged nor relayed, never observed into the clock. | `an op the engine cannot index by is malformed: counted, never logged`; `a stamp beyond maxSkew is refused and never observed into the clock` |
| SYNC-4 | A node's own sequence never repeats: the log is written before the op is announced, and a reopen recovers the seq from the log. | `reopen restores epoch, next, vector and entries`; `identity, seq and vector survive a reopen; what was logged but not written is replayed` |
| SYNC-5 | Logged means applied, eventually: the append is the commit point, a batch seals only once its records were written, and a write whose file failed is held and reported. | `survives a torn open file, a lost index and a duplicated roll`; `identity, seq and vector survive a reopen; what was logged but not written is replayed`; `a copy that cannot be written stops the write; a torn copy is evidence; a purge reaches the tags` |
| SYNC-6 | A disconnect and a reconnect resume from the last event id, both ways; a failed push leaves the peer behind and the next sign of life catches it up. | `a disconnect and reconnect resumes from the last event id, both ways`; `a page from the host triggers the recovery`; `pushes to one peer never overlap: handshake, relay and sync() take turns` |
| SYNC-7 | A node that cannot be resumed bootstraps from a snapshot; the joined state is transitive and never echoes back to the node it came from. | `a late joiner bootstraps from a snapshot once history is compacted`; `snapshot pages every entry, tombstones included; mergeSnapshot joins them`; `a page of nothing but echoes moves the cursor and announces nothing` |
| SYNC-8 | A host checks, every node decides: a skipped op is still logged and relayed; what stops at the host is out of scope, malformed, skewed, unsigned where required, or a throwing hook. | `beforeApply(false) skips an op here: logged, relayed, replay-safe`; `a skip is local: the op still reaches the peers behind this node`; `the hosting unit refuses what it must`; `scopes: a node syncs only what it asked for, plus everything global` |
| SYNC-9 | Every op is signed by its origin's key and the node id is that key; a signed op relays intact through a node that does not verify. | `signOp fills nonce, digest and sig; verifyOp answers every row of the table`; `a signed op relays intact through a node that does not verify, into one that requires` |
| OPS-1 | A field is a register, a counter, a set, a list, a text or a tree — one of them, never two; mixing is refused locally and from a peer, and a merge keeps the precedence. | `a field is a register, a counter or a set — never two of them`; `a list or a text is never also a register, a counter or a set`; `mergeEntry joins two sequence histories like replaying both; kinds keep their precedence`; `a tree moves through applyOp; concurrent moves that would make a cycle leave one in effect` |
| OPS-2 | A reset (write, delete) drops what is stamped below it, and the same predicate guards each op as it applies, so meta — not only data — agrees whatever the order. | `a reset drops set tags older than it and clamps the rest, so metas agree too`; `a reset drops counter entries older than it`; `a text converges: concurrent inserts, cuts, extensions and a reset, in any order` |
| OPS-3 | A purge wins at any stamp, forever; the payload leaves the log, the tags and every peer that learns of it. | `purge wins at any stamp, forever; a merge with a purged side is purged`; `after a purge nothing of the record is left, and nothing later revives it`; `a snapshot that carries a purge scrubs what the joiner held of the record` |
| OPS-4 | A peer-shaped meta reaches nothing it should not: own keys only, well-formed stamps alone. | `normalizeMeta rebuilds a merge meta from own keys and well-formed stamps alone`; `fields named after Object.prototype members are fields; __proto__ never is` |
| OPS-5 | Encrypted records are sealed for this node's key alone and do not sync. | `encrypted records stay local`; `encrypted writes go through the same hooks and stay local` |
| OPS-6 | Hooks run inside the operation and may refuse it; events never break a write. | `a throwing beforeWrite refuses the write: nothing stamped, logged or written`; `a change listener that throws does not fail the write it observed`; `a hook cannot write to the storage, but it can read` |
| LIST-1 | Two writers inserting at one spot both keep theirs, each writer's run whole: words typed apart never interleave. | `lists and texts converge: concurrent inserts and cuts, each writer’s run whole`; `three nodes type words apart; after the merge every word is whole` |
| LIST-2 | A concurrent move of one element lands it once, at the newer move's place; a value set follows the element. | `a list moves and assigns through applyOp; concurrent moves leave the element once`; `setAt and move keep an element’s name; a move names where it shows` |
| LIST-3 | A mark is two anchors picked by its expand rule; the newest per name wins, a stacking mark goes only by id. | `a mark rides on a text through applyOp; a list, a register or a counter refuses it`; `mark, unmark and spans: styles grow as their expand rule says, stack when many` |
| LIST-4 | A cursor names a place that survives the edits around it. | `a cursor names a place that survives the edits around it` |
| LIST-5 | A tree's moves fold in stamp order and a cycle never forms: of two concurrent moves that would make one, the older stands on every node. | `concurrent moves that would make a cycle: exactly one takes, the same one everywhere`; `treeMove and treeRemove keep a movable tree; a cycle is refused inside the queue` |
| LOG-1 | The log knows what it dropped: `droppedTs` is the newest stamp compaction took or an open could not read, and a pin holds a segment past retention. | `droppedTs is the newest stamp compaction dropped; a pin holds a segment past retention` |
| LOG-2 | A node's own ops are kept for the nodes it dials until they hold them; a host behind what the log retains is reported, not fed gaps. | `the outbox is bounded: beyond maxOutbox the backlog is dropped and the peer is behind`; `a push answers with the keys it touched; a second snapshot page carries no vector` |
| VER-1 | A version read from the log is exact while nothing was dropped, and from a reset stamped above `droppedTs` after; what cannot be given exactly is refused, never guessed. | `compaction: the past is exact from a reset above what was dropped, gone before it`; `a counter incremented across the reset compaction crossed makes the past inexact`; `a snapshot joined after a stamp hides what it carried: HISTORY_GONE merge` |
| VER-2 | An event id is what this node held; a stamp and a vector are what was written by then, the same on every node that holds the ops. | `an event id is what this node held; a stamp and a vector are what was written by then`; `history() lists one version per op, newest first; get(id, { at }) reads each back` |
| VER-3 | A tag reads records as they were: a copy lands in the newest tag only, once per record, before its first change, and moves down when the tag goes. | `a tag reads records as they were: after an update, a delete, an insert, through the lens`; `copies land in the newest tag only, once per record, and move down when it goes`; `queries, the list and a snapshot at a tag read the storage as it was` |
| VER-4 | A restore is new ops that lead back: a version of its own that merges like any write. | `restore() reads as the version, through every kind, and merges like any write`; `diff() names what turns one version into another, per field by kind` |
| VER-5 | An undo is new ops too: a field anyone else changed since is left alone, and an undone add revokes this node's adds alone. | `a field a peer changed since is left alone; a whole-record step needs force`; `an undone add revokes its own tag alone; counters undo across nodes` |
| VER-6 | A branch is a storage under a new identity; a merge hands over exactly what the other side lacks, and a second merge has nothing to hand over. | `a fork stands at the parent under a new identity; merges go both ways`; `a parent that compacted past the fork is joined as state; signatures are required and met` |
